# Capture working conventions

Read [the runtime adapter](references/runtime.md), then the installed skill-creator and writing-for-agents guidance before authoring. Locate an existing personal mode and preserve its established home when updating it.

Use the history scope the user authorized. If none is given, mine only the active project's recent conversations. Find repeated original user preferences about response style, autonomy, verification and process. Require evidence in at least two independent conversations or an explicit current user instruction. Treat relays, duplicated imports and task-specific limits separately. Record contradictions instead of averaging them into a rule.

Group only the conventions that change behavior. Compare them with existing project instructions, Veil or other shared rules and the host defaults. Reference an existing source rather than restating it. Keep platform tool mappings in the runtime adapter; keep personal preferences in the personal skill.

Ask one compact clarification round only when unresolved intent would materially change the result. If the evidence already supports a draft, write it for review. Use a name and description that identify the person's working style and a narrow trigger. Preserve an existing invocation policy. New skills follow the authoring tool's normal discovery default unless the user chooses explicit-only invocation.

Give each proposed convention a source pointer in working notes. Keep the installed skill short and operational. Apply unslop if available, validate frontmatter and references, and report uncertain choices. A request to draft a mode does not itself authorize publishing a PR or changing global agent rules. Do not create another canonical memory system.
